## 液滴计数重复计数 bug 修复
- 现象：前端首测 60 秒 148 滴，但滴液时刻 8.9s/9.0s/9.1s 间隔仅 0.1~0.2s，同一液滴被重复计数（Python 端 0~60s 应约 109 滴）
- 根因：
  - MIN_GAP=2 帧（30fps 下仅 0.067s）冷却太短，挡不住液滴穿过检测区的"多峰"（前沿/后沿各一次差分峰）
  - RESET 复位逻辑太敏感，液滴在检测区内能量阈值附近波动时反复触发 DROPLET→IDLE→DROPLET
- 修复：改用固定冷却时间 REFRACTORY=0.25s（与 Python 端 min_gap=15帧@60fps=0.25s 一致）
  - 状态机改为 IDLE → REFRACTORY，计数后冷却期内不再计数，冷却结束恢复 IDLE
- 构建通过（vite build 14.96s 无错误）

## 视频预览画面自适应（横竖屏无黑边 + ROI 对齐）
- 需求：导入的视频不同分辨率/横竖屏要自适应容器，不变形、不溢出、不黑边
- 根因：视频预览容器固定高度（440px/400px），video object-fit:contain 后横竖屏留大黑边，且 ROI 框（相对容器百分比）与视频实际画面（留黑边居中）错位
- 方案：容器 aspect-ratio 跟随视频宽高比
  - CSS：容器用 `aspect-ratio: var(--video-ratio)` + `max-height` + `max-width: calc(440px * var(--video-ratio))`（比例保持 + 高度受限时宽度自动收缩）
  - JS：视频 loadedmetadata 时读 videoWidth/videoHeight，设置 `--video-ratio` CSS 变量
- 涉及：VideoRecognitionDemo（.uploaded-video-wrap）、DropletCounterDemo（.droplet-stage）
- 验证（playwright 4/4）：横屏 640x360 容器比例 1.780≈1.778 ✓；竖屏 360x640 容器 248x440 比例 0.564≈0.562 ✓（两组件均通过）
- 已提交 git（commit 4c8962d）
