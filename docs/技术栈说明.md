## 1. 最终技术路线

本项目最终采用以下技术组合：

```text
Web 前端：
Vue 3 + TypeScript + Vite + Element Plus + ECharts

后端服务：
Java 17 + Spring Boot 3 + MyBatis-Plus + Spring Security + JWT

数据库：
MySQL 8

视觉检测端：
Python + PySide6 + OpenCV + NumPy + PyQtGraph

部署与打包：
Nginx + Docker Compose + PyInstaller
```

该方案将教学管理、业务接口和视觉算法分层实现：

- Vue 前端负责学生、教师、管理员的 Web 操作界面；
- Java 后端负责登录认证、权限控制、实验任务、实验记录、批注评分、文件管理和统计接口；
- Python 检测端负责摄像头采集、ROI 框选、HSV 颜色识别和滴定终点判定；
- MySQL 负责保存用户、任务、实验记录、颜色数据、评分和系统配置。

## 2. 总体架构

```text
学生 / 教师 / 管理员
        ↓ 浏览器访问
Vue 3 教学管理平台
        ↓ Axios / HTTP API
Spring Boot 后端服务
        ↓
MySQL 数据库 + 本地文件存储
        ↑
Python 本地视觉检测端
PySide6 + OpenCV + NumPy
        ↑
实验室摄像头
```

### 2.1 Web 教学管理平台

Web 平台用于处理多角色用户管理和教学业务，包括：

- 学生登录和查看实验任务；
- 学生查看个人实验记录、识别结果和教师反馈；
- 教师发布实验任务、查看学生提交记录、批注和评分；
- 管理员维护用户、角色、班级、阈值模板和系统配置。

### 2.2 Java 后端服务

Java 后端作为系统业务中心，负责：

- 用户认证与 JWT 签发；
- 学生、教师、管理员 RBAC 权限校验；
- 实验任务、实验记录、颜色采样数据、状态事件的增删改查；
- 检测端上传实验结果、关键帧和视频文件；
- 教师批注、评分和统计数据接口；
- 文件路径、阈值模板和系统配置管理。

### 2.3 Python 本地视觉检测端

Python 检测端运行在实验室电脑，负责实时视觉处理：

- 摄像头接入和实时预览；
- ROI 区域框选；
- 图像去噪、光照处理和 HSV 转换；
- 初始色、过渡色和终点色识别；
- 纯蓝色稳定 30 秒终点判定；
- 保存关键帧、视频和实验日志；
- 将实验结果上传给 Java 后端。

## 3. 为什么选择 Java 后端

项目包含学生、教师、管理员三类用户，以及登录、权限、实验任务、实验记录、批注评分和统计分析等典型管理系统功能。相比全 Python 后端，Java Spring Boot 更适合承载这部分业务。

主要理由如下：

| 原因 | 说明 |
| --- | --- |
| 工程完整度高 | Spring Boot 适合构建正式的管理系统，项目结构清晰，答辩表达更完整 |
| 权限体系成熟 | Spring Security + JWT + RBAC 适合实现三类角色权限控制 |
| CRUD 开发效率高 | MyBatis-Plus 对 MySQL 增删改查、分页、条件查询支持成熟 |
| 文件上传方便 | Spring Boot 可稳定处理关键帧、视频、Excel 等文件上传下载 |
| 与 Vue 配合成熟 | Vue + Spring Boot 是常见前后端分离毕设组合 |
| 教学管理业务更贴合 | 实验任务、批注评分、用户管理等业务更像 Java 管理系统 |

Python 仍然保留在视觉检测端，用于 OpenCV 图像处理，这是 Python 最擅长的部分。

## 7. Python 本地视觉检测端技术栈

### 7.1 核心依赖

| 技术 | 作用 |
| --- | --- |
| Python 3.11 或 3.12 | 检测端开发语言 |
| PySide6 | 构建 Windows 桌面图形界面 |
| OpenCV | 摄像头采集、视频录制、ROI、滤波、HSV 转换和关键帧保存 |
| NumPy | 像素统计、阈值匹配和置信度计算 |
| PyQtGraph | 实时绘制 HSV 曲线 |
| httpx 或 requests | 调用 Java 后端 API 并上传实验结果 |
| pandas | 整理实验数据 |
| openpyxl | 导出 Excel 文件 |
| PyInstaller | 打包 Windows exe |
| pytest | 算法和状态机测试 |

### 7.2 核心算法流程

```text
摄像头采集
  ↓
用户框选 ROI
  ↓
高斯滤波与光照处理
  ↓
BGR 转 HSV
  ↓
提取 H、S、V 与颜色像素占比
  ↓
阈值匹配与时间窗口平滑
  ↓
状态机判断
  ↓
纯蓝色稳定 30 秒
  ↓
确认有效滴定终点
  ↓
保存并上传实验数据
```

### 7.3 状态机

```text
待机
  ↓
采集准备
  ↓
初始色
  ↓
滴定中
  ↓
临近终点
  ↓
候选终点
  ↓ 纯蓝色稳定 30 秒
有效终点
```

候选终点期间若出现返色、颜色明显波动或匹配度持续不足，应清空稳定计时并返回实时检测状态。

## 9. 用户认证与权限控制

### 9.1 认证方式

推荐使用 Spring Security + JWT：

```text
用户登录
  ↓
Spring Security 校验账号和密码
  ↓
后端签发 JWT
  ↓
前端或 Python 检测端携带 Token 调用 API
  ↓
后端校验 Token 和角色权限
```

密码必须使用 BCrypt 等不可逆哈希算法保存，不得存储明文密码。

## 14. 暂不建议使用的技术

| 技术 | 原因 |
| --- | --- |
| 深度学习模型 | 首期颜色分类使用 HSV 即可完成，深度学习需要额外标注数据和训练成本 |
| Kubernetes | 项目规模较小，Docker Compose 足够 |
| 微服务架构 | 会增加部署和联调复杂度，不利于毕设按期完成 |
| Redis | 首期没有高并发缓存需求，可按实际情况后续引入 |
| 云对象存储 | 首期服务器本地文件目录已能满足实验数据保存需求 |
| 全 Java 视觉处理 | OpenCV Python 生态更适合快速完成摄像头和颜色识别算法 |
| 全 Python 后端 | 管理系统和权限业务使用 Java 更有工程完整度 |

---

## 15. 最终技术选型结论

本项目最终确定采用：

```text
Vue 前端 + Java Spring Boot 后端 + Python OpenCV 检测端
```

该方案的职责划分清晰：

- Vue 负责界面展示和用户交互；
- Java 负责平台业务、权限认证、数据存储和文件管理；
- Python 负责计算机视觉检测和滴定终点识别；
- MySQL 负责统一保存教学管理与实验数据。

该技术路线既能体现计算机视觉特色，又能形成完整的教学管理系统，更适合作为毕业设计的正式实现方案。
